2. 합친 아이디어와 묶음

12개 아이디어를 계산 방식과 업무 흐름이 비슷한 것끼리 5개 묶음으로 합쳤다. 묶음 하나가 대시보드 카드 한 장이다.

A. 컨테이너 재고·공이송

hjung · 권도윤

공컨테이너 과부족 판단 → 공이송안

hjung 이 지역별 재고를 적정재고와 비교해 과잉/부족을 가려내면, 권도윤 이 그 결과에 모선 기항 순서와 잔여 스페이스를 얹어 이송 수량안을 만든다. 한 카드에서 "어디가 남고 어디가 모자란지 → 어느 모선으로 얼마 옮길지"가 이어진다.

카드 숫자: 과잉/부족 지역 수 / 이송안 구간 수

B. 반납·CY 재고 대조

전지연 · 전성현

반납 대상·CY 수량을 기준 자료와 대조해 확정

전지연 은 CY 메일 수량과 포탈 수량을, 전성현 은 오늘과 어제 반납 대상을 대조한다. 둘 다 "두 표를 맞춰 다른 곳만 보여주는" 같은 계산이라 lib/compare.md 하나를 함께 쓴다.

카드 숫자: CY 불일치 건수 / 신규 반납건·반납번호 확보율

C. 위험물·스페셜화물 확인

kim jaehyung · 김유민 · 이병선

위험물 서류 일치 → 규정 판정 → 회신 초안

김유민 이 CERTI 와 SPECIAL LIST 가 맞는지, kim jaehyung 이 승인 요청 첨부 서류가 빠짐없는지 보고, 이병선 이 내규 금지 매트릭스와 사고 이력으로 가능/불가/검토 필요를 판정한다. 같은 스페셜화물 흐름의 앞·가운데·끝이라 한 카드로 합친다.

카드 숫자: 점검 건수·불일치 건수 / 가능/불가/검토 필요 건수

D. 선박 운영 수치(벙커·용선료·보급)

다니엘 · ijryu · 황심연

선박 운영 수치 계산, 사람은 확인 필요만

다니엘 의 속도별 소모량, ijryu 의 Off-hire 차감 협정, 황심연 의 스페어파트 부족 선박은 모두 선박별 숫자를 엑셀로 계산하고 이상한 칸만 사람에게 넘기는 일이다. 선박 단위 숫자라 한 카드에 모은다.

카드 숫자: 제외·이상 구간 수 / 진행 중 협정·부족 선박 수

E. 평택 스케줄·실적

노현석 · 이예윤

평택사무소 입항 마감 + 월간 실적

이예윤 의 이번 주 입항 선박 마감표(D-day)와 노현석 의 월간 거래처 실적(수출·수입 TEU 전월 비교)을 평택사무소 한 카드로 본다. 마감이 급한 건과 방문할 화주를 한 화면에서 정한다.

카드 숫자: D-3 이내 마감 수 / 전월 대비 TEU 증감

공통으로 보이는 일: ① 두 표 맞춰 다른 곳만 보기 ② 기준표와 비교해 과잉/부족 가르기 ③ 집계하고 전월과 비교하기 ④ 일정 창과 마감 계산하기 → lib/ 공통 규칙으로 한 번만 만든다.

5. 공통 결과 파일 꼴

에이전트마다 data/out/<이름>.json 한 개를 낸다. 대시보드는 이 꼴만 읽는다.

{
  "schema_version": 1,
  "agent": "bunker-consumption",
  "owner": "다니엘",
  "bundle": "D",
  "as_of": "2026-10-22",
  "headline": "3척 처리, 제외 12일(8%), 확인 필요 2건",
  "metrics": [
    { "key": "processed", "label": "처리 건수", "value": 3, "unit": "척", "prev": 3 },
    { "key": "excluded_ratio", "label": "제외 비율", "value": 8, "unit": "%", "prev": 6 }
  ],
  "table": {
    "columns": ["선박코드", "속도(kn)", "일일 소모량(t)"],
    "rows": [["S01", 12, 28.4], ["S01", 14, 36.1]]
  },
  "review": [
    { "id": "R01", "code": "S02", "reason": "평균 대비 큰 이탈", "detail": "S02 10/03 소모량 이탈 폭 큼" }
  ],
  "time": { "before_min": 10, "after_min": 2, "runs_per_month": 30, "basis": "추정" },
  "source": { "label": "가상 항해 일지", "rows": 365 },
  "rules_version": "aggregate@v1",
  "synthetic": true
}
칸뜻
schema_version결과 파일 꼴의 버전. 지금은 1
agent · owner · bundle에이전트 이름(영문 슬러그) · 만든 조원 · 묶음 기호(A~E)
as_of계산 기준 날짜(YYYY-MM-DD)
headline카드 맨 윗줄에 그대로 쓰는 한 줄 요약
metrics[]카드 숫자들. key · label · value · unit · prev(전회 값, 없으면 생략)
table카드를 눌렀을 때 펼치는 표. columns 와 rows
review[]확인 필요 목록. id · code · reason · detail. detail 은 이미 코드로 가린 문장만
time걸린 시간 전/후(분), 월 실행 횟수, basis(추정 또는 측정). 월 절감 시간 = (전−후)×횟수÷60
source입력 자료 이름표와 행 수. 파일 이름·경로는 쓰지 않는다
rules_version어느 lib/ 규칙 버전으로 계산했는지
synthetic가상 데이터이면 true

공통 계산 규칙 (lib/)

파일담는 규칙쓰는 조원
lib/compare.md두 표 대조: 표기 통일(UN1263=1263, 18,000=18000 KGS), 키로 짝 맞추기, 일치 / 불일치 / 짝 없음 판정전지연 · 김유민 · 전성현 · 이예윤 · kim jaehyung

lib/aggregate.md집계 · 전월 비교 · 신규/이탈 표시 · 이상치 제외 · 전/후 시간 계산다니엘 · ijryu · 노현석
lib/schedule-window.md일정 창(오늘 기준 7~21일) 찾기, 선적지별 마감 계산, D-day이예윤 · 황심연 · 권도윤

7. 폴더 구조 · 대시보드 방식 · 지킬 것

seoul-ax-jo1/
├─ CLAUDE.md                    ← 이 폴더의 약속(역할 표 · 과제 · 6교시 역할 메모)
├─ 설계.md / 설계.html          ← 설계 문서
├─ 역할메모.txt
├─ 아이디어/                    ← 조원 아이디어 파일(PDF 또는 md) 모아 두는 곳
├─ agents/
│   └─ <에이전트>/
│       ├─ SKILL.md             ← 에이전트 지시서(스킬을 부르는 순서)
│       └─ skills/<스킬>/SKILL.md
├─ lib/                         ← 공통 계산 규칙(compare · threshold · aggregate ·
│                                 schedule-window · special-cargo-rules · mask · result-shape)
├─ data/
│   ├─ in/                      ← 가상 샘플 엑셀·PDF
│   └─ out/                     ← 에이전트마다 결과 파일 1개(<이름>.json)
├─ dashboard/                   ← 장금상선 AX 대시보드(브라우저에서 계산)
└─ deck/                        ← 발표 자료

대시보드 방식

  • 부서 엑셀을 브라우저 안에서 lib/ 규칙으로 계산한다. 엑셀 원본은 서버로 보내지 않는다.
  • AI 는 이름을 가린 확인 목록만 정리한다. 계산은 AI 가 하지 않는다.
  • 기본 화면은 data/out/ 결과 파일로 그리고, 엑셀을 올리면 같은 꼴을 브라우저에서 만들어 덮어 보여 준다.

지킬 것

  • 가상 데이터만 쓴다. 실제 선박명·컨테이너 번호·화주·금액·용선료는 넣지 않는다.
  • 보내기 기능은 만들지 않는다. 메일·알림은 초안 글만 화면에 보여 주고, 발송은 사람이 직접 한다.
  • API 키는 .env.local 과 버셀 환경 변수에만 둔다. 코드·문서·깃·대화 어디에도 적지 않는다.
  • 실제 자료를 올리게 되면 대시보드에 입장 비밀번호를 먼저 건다(비밀번호도 환경 변수).
  • AI 에는 이름을 가린 확인 목록(선박·컨테이너·화주를 S01·C01·H01 같은 코드로 바꾼 것)만 보낸다. 엑셀 원본은 보내지 않는다.
  • 숫자는 규칙(lib/)이 계산한다. AI 는 계산하지 않고 확인 목록의 문장 정리만 맡는다.
  • 확신이 낮은 값은 맞다고 처리하지 않고 "확인 필요"로 넘긴다. 최종 결정은 사람이 한다.
확인 필요: 역할메모.txt 와 아이디어/ 안의 PDF 는 이 PC 의 작업 폴더에서 찾지 못했다. 조원 아이디어는 폴더 안의 내병목_*.md 와 이병선_스페셜화물_승인_업무_자동화_제안.md 12개에서 읽었다. 역할메모.txt 를 찾으면 CLAUDE.md 끝의 「6교시 역할 메모」에 그대로 붙이고 역할 표와 맞는지 본다.
