# 내 병목 · 이병선 (장금상선 운항팀)

## 1. 프롬프트

### 업무자동화 진단 워크시트

나는 장금상선 운항팀으로 일하고 있고, 다음의 번거롭고 반복적인 업무를 AI로 개선하고 싶어.

■ 내 업무 키워드 (일의 흐름 순): STOWAGE PLANNING → 스케쥴 관리 → 스페셜화물 승인
■ 번거로운 업무: 스페셜화물 승인 — 화주로부터 스페셜 화물 (위험물, OOG화물 등) 승인 요청을 받으면 운항팀에서 건건히 확인하여 선적 가부를 판단하여 승인 또는 미승인 함.
■ 이 업무를 고른 이유: 매일 반복 되는 업무입니다.
■ 빈도/소요 시간: 일 30회, 회당 약 1분 (월 약 10.9시간)
■ 이 업무가 존재하는 이유: 회사 내부에서 선적을 금지하는 항목이 실시간으로 업데이트 되기 때문에 담당자의 확인이 필요합니다.

■ Input (넣는 것): 위험물 또는 OOG화물의 스펙과 선적지/양하지를 넣으면
■ Output (나오길 바라는 것): 내규에 따라 선적 가능 여부

■ 업무 프로세스:
  1. 위험물 또는 OOG화물의 스펙과 선적지/양하지를 넣으면
  2. 선적 금지 품목 관련 내규 확인, 최근 타 사에서 해당 품목으로 인한 사고 사례가있었는지 확인 ← 🔴 비효율 (내규에 따라 선적금지 리스트에 존재여부만 단지 확인 하는 작업일 수 있음.)
  3. 내규에 따라 선적 가능 여부

이 업무 중 다음 지점이 비효율이라고 판단했어:
- 2단계 "선적 금지 품목 관련 내규 확인, 최근 타 사에서 해당 품목으로 인한 사고 사례가있었는지 확인": 내규에 따라 선적금지 리스트에 존재여부만 단지 확인 하는 작업일 수 있음.

■ 우선순위: 선적 금지 품목 관련 내규 확인, 최근 타 사에서 해당 품목으로 인한 사고 사례가있었는지 확인 ⭐ 최우선 (비효율 지점이 한 곳)

내가 내 업무의 비효율을 제대로 짚었는지, 어떻게 하면 아래의 AI 도구를 접목해서 자동화할 수 있는지 알고 싶어. 업무자동화 아이디어를 얻을 수 있도록 나를 인터뷰해줘. ⭐ 최우선 지점부터 한 번에 하나씩 질문하고, 인터뷰가 끝나면 우선순위가 낮은 지점까지 포함해 각 지점별 자동화 아이디어를 정리해줘.

### 요청

위 내용은 내가 업무자동화 진단 워크시트로 찾은 내 업무 병목이야. superpowers brainstorming 으로 정리해줘. 코드는 아직 만들지 마. 이해한 내용을 먼저 정리하고, 이 병목을 줄일 에이전트 · 스킬 후보 2~3개를 장단점과 함께 비교해줘. 질문은 한 번에 하나씩 보기와 함께, 3개까지만 하고 나머지는 네 추천안으로. 정리가 끝나면 「병목 · Input → Output · 내가 만들 에이전트 1개 · 스킬 2~3개 · 조 대시보드에 보탤 결과」를 한 쪽 분량으로 정리해줘. 그다음 이 정리로 6교시 조별 모임에서 조원에게 3분 안에 말로 소개할 수 있게 슬라이드 5장 이내로 만들어줘. 1장 나는 누구 · 어떤 업무, 2장 일의 흐름과 병목, 3장 얼마나 걸리나, 4장 이렇게 바뀌면 좋겠다(Input → Output), 5장 조 대시보드에 보탤 수 있는 것과 조원에게 묻고 싶은 것. 장마다 글은 3줄 이내로 크게. 파일은 내병목소개_이병선.html 한 파일, 키보드 화살표로 넘기고 휴대폰에서도 보이게. 같은 슬라이드를 내병목소개_이병선.pdf 로도 저장해줘 (가로 16:9, 한 쪽에 슬라이드 한 장). 다 만들면 PDF 를 열어줘. 그리고 위 프롬프트와 한 쪽 정리를 내병목_이병선.md 파일로도 저장해줘.

## 2. 한 쪽 정리

### 병목
스페셜화물(위험물, OOG) 승인 요청마다 **내규 문서를 찾아 대조**하고, **타사 사고 사례를 기억에 의존해** 떠올리는 2단계.
- 내규는 Word/PDF 문서이고 선사가 **몇 달에 한 번** 개정함. 실시간 변경이 아니므로 미리 표로 정리해 둘 수 있음.
- 조항은 "품목 + 항만/항로 조건" 형태라 대부분은 규칙 대조로 판정 가능. 애매한 건만 담당자 판단이 필요함.
- 사고 확인은 시간보다 **품질 문제**: 담당자가 바뀌거나 못 들은 사고는 판단에서 빠짐.

### Input → Output
- **Input:** 화주의 승인 요청 이메일 (UN No., 품명, Class, 포장 등급, 수량 / OOG 치수·중량, POL·POD·환적항)
- **Output:** **가능 / 불가 / 검토 필요** 판정 + 근거 내규 조항 + 동일 품목 사고 이력 + 회신 메일

### 내가 만들 에이전트 1개 — 스페셜화물 승인 에이전트 (Claude Code)
1. Outlook 받은편지함에서 새 승인 요청 메일을 찾음 (Microsoft 365 연동)
2. 메일 본문과 첨부에서 스펙 추출. 빠진 항목은 화주에게 보낼 보완 요청 초안 작성
3. 금지 매트릭스와 사고 DB로 판정
4. **명확한 가능·불가는 자동 회신**, '검토 필요'는 담당자에게 넘김
5. 모든 판정과 회신을 기록 (근거 조항 포함)

안전장치: 처음 몇 주는 **초안 모드**로 운영해 판정 정확도를 확인한 뒤 자동 회신으로 전환함. 애매한 조건, 매트릭스에 없는 품목, 추출 실패 건은 항상 '검토 필요'로 분류함.

### 스킬 3개
| 스킬 | 하는 일 | 언제 |
|---|---|---|
| 내규 → 금지 매트릭스 변환 | 내규 문서를 품목 × 항만 × 선적/양하/환적 × 판정 × 근거 조항 표로 변환. 개정본이 오면 이전 표와 비교해 바뀐 조항 표시 | 내규 개정 시 (몇 달에 한 번) |
| 스페셜화물 판정 | 스펙과 POL/POD를 매트릭스와 대조해 판정 + 근거 조항 제시 | 요청마다 (일 30건) |
| 사고 사례 수집 | 매주 해사 뉴스와 사고 공지를 검색해 위험물 사고를 UN No.별로 사고 DB에 누적 | 매주 예약 실행 |

### 조 대시보드에 보탤 결과 — 절감 시간
- **절감 시간 = 자동 처리 건수 × 1분** (판정 기록에서 주간 집계)
- 함께 표시: 전체 요청 건수, 자동 처리 비율, '검토 필요' 비율
- 예시 계산: 요청의 70%가 자동 처리되면 월 10.9시간 중 약 7.6시간 절감 (70%는 가정이며 시험 운영으로 확인)
