# 집계 규칙 (aggregate@v1)

월·건 단위 자료를 묶어 합계를 내고, 지난달과 비교하고, 신규·이탈을 표시하고, 걸린 시간 전/후를 계산하는 규칙. 읽는 이: 노현석(영업실적) · 다니엘(소모량) · ijryu(Off-hire).
코드는 영업실적이 `dashboard/js/sales/rules.js` 이고, 화면·결과 파일·테스트가 모두 이 코드를 쓴다. 이 문서와 코드가 다르면 코드가 기준이고, 문서를 고친다.
(소모량 분석의 이상치 제외 · 숫자표와 Off-hire 의 상태별 건수는 각 담당이 이 문서에 이어서 쓴다.)

## 공통 규칙

| 규칙 | 내용 |
|---|---|
| 집계 | 건별 행을 키(화주 · 구분 · 항구 등)로 묶어 더한다. 같은 자료를 기준만 바꿔 여러 번 묶을 때는 두 방식의 합계가 같은지 검산한다 |
| 전월 비교 | 이번 달 − 전월 = 증감, 증감 ÷ 전월 = 증감률(소수 첫째 자리). 전월이 0 이면 증감률은 `-`. **전월 자료를 고르지 않았으면 비교 칸은 `확인 필요`** 로 두고 0 으로 채우지 않는다 |
| 신규 · 이탈 | 전월 0 이고 이번 달 > 0 → `신규`. 이번 달 0 이고 전월 > 0 → `이탈`. 구분(수출/수입)마다 따로 본다 |
| 증가 · 감소 | 신규·이탈이 아니고 증감이 숫자표의 기준(TEU) 이상이면 `증가`, 이하(음수)이면 `감소`. 기준 미만의 차이는 비고를 비운다 |
| 읽지 못한 값 | 맞다고 처리하지 않고 집계에서 빼서 `review`(확인 필요)로 넘긴다. 뺀 줄도 원본 합계 검산에는 넣는다 |
| 걸린 시간 | `time` = 전(분) · 후(분) · 월 실행 횟수 · 근거(`추정` 또는 `측정`). **월 절감 시간 = (전 − 후) × 횟수 ÷ 60** |
| 이름 가림 | 결과 파일·AI 에는 이름을 코드로 바꿔 보낸다(lib/mask.md). 화면 안에서만 이름을 쓴다 |

## 영업실적 (노현석) — 월간 거래처 집계

평택사무소의 월별 거래처 수출입 실적을 화주별 · 항구별로 묶어 전월과 비교한다. 단위는 TEU.

### 자료

| 파일 | 담는 것 |
|---|---|
| `data/in/sales-analysis/demo-monthly-sales.xlsx` | 가상 월별 실적 엑셀. 건별 한 줄: `월 · 화주 · 구분 · POD/POL · TEU`, 2026-09 · 2026-10 두 달(204건). `node scripts/make-sales-sample.mjs` 로 다시 만든다 |

머리글 이름은 아래 말도 받는다(칸 순서는 상관없음): 월(`선적월 · 기준월 · 일자`) · 화주(`거래처`) · 구분(`수출입`) · POD/POL(`항구`) 또는 `POD` · `POL` 두 칸 · TEU(`물량`). 월은 `2026-10` · `2026.10.05` · `2026년 10월` · `202610` · 엑셀 날짜를 모두 읽는다.

### 표기 통일 (lib/compare.md 와 같은 취지)

| 칸 | 규칙 |
|---|---|
| 구분 | `수출 · EXP · Export` → `수출`, `수입 · IMP · Import` → `수입`. 그 밖의 말은 읽지 못한 것 |
| 화주 | 공백 정리, `(주)` · `㈜` · `주식회사` 표시 제거 |
| 항구 | 공백 정리, 영문이면 대문자(`Shanghai` → `SHANGHAI`). `POD/POL` 한 칸이면 그 값을, 두 칸이면 수출은 POD · 수입은 POL 을 쓴다 |
| TEU | `1,200` · `12 TEU` 를 숫자로. 숫자가 아니거나 0 이하이면 읽지 못한 것 |
| 합계 줄 | 월 칸이나 화주 칸이 `합계 · 총계 · 소계 · Total` 이면 건이 아니므로 건너뛴다 |

월 · 화주 · 구분 · 항구 · TEU 중 하나라도 비었거나 읽지 못한 줄은 집계에서 빼고, 줄 번호와 이유를 알리고, `review` 에 「건너뛴 줄」 한 줄을 넣는다.

### 숫자표 (코드 = `rules.js` 의 `NUMBERS`)

| 항목 | 값 | 뜻 |
|---|---|---|
| 증가 · 감소 기준 | 5 TEU | 전월 대비 5 TEU 이상 늘면 증가, 5 TEU 이상 줄면 감소(비고). 4 TEU 차이는 비고 없음 |
| 줄어든 항로 기준 | 5 TEU | 항구 하나의 물량이 전월보다 이만큼 줄면 방문 목록의 「줄어든 항로」에 올린다 |
| 영업 카드 항구 | 상위 3 | 수출 도착지 · 수입 선적지 각각 |
| 보고서 항구 칸 | 8 | 항구가 8곳을 넘으면 위 7곳 + `기타` |
| 걸린 시간 | 전 60분 → 후 15분 | 월 22회(추정). 「내병목」 워크시트의 영업 업무 주 5회 × 60분 |

숫자를 바꾸면 `RULES_VERSION` 을 올린다.

### 집계 순서

1. 읽은 건을 이번 달 · 전월로 나눈다(전월은 사람이 고르거나, 고르지 않으면 엑셀의 바로 앞 달).
2. 구분(수출/수입)마다 화주별로 묶는다: 이번 달 · 전월 · 증감 · 비고 · 항구별 TEU. 정렬은 **이번 달 TEU 큰 순 → 같으면 이름 순 → 이탈은 맨 아래**.
3. 구분마다 항구별로 따로 묶는다(수출은 도착지, 수입은 선적지): 이번 달 · 전월 · 증감 · 화주 수.
4. 검산 5개: ① 원본 합계 = 표 합계 + 뺀 줄 ② 화주별 합계 = 그 화주의 항구 칸 합 ③ 수출 항구 칸 합계 = 수출 표 합계 ④ 수입 항구 칸 합계 = 수입 표 합계 ⑤ 전월 합계 = 전월 자료 합계. 하나라도 틀리면 결과 파일 `review` 에 「합계 불일치」 한 줄을 넣는다.

### 방문 목록 순서

사유 순서: **이탈 → 큰 폭 감소 → 신규 → 증가**. 같은 사유 안에서는 이탈은 전월 물량이 큰 순, 감소는 많이 줄어든 순, 신규·증가는 이번 달 물량이 큰 순. 전월 자료가 없으면 목록을 만들지 않는다. 항로는 증감이 가장 많이 줄어든 순으로 따로 보여 준다.

### 결과 파일 (`data/out/pyeongtaek-sales.json`)

- `headline`: `수출 241 TEU(+9.5%) · 수입 158 TEU(-2.5%), 신규 2 · 이탈 2`
- `metrics`: `processed`(거래처 수) · 수출 · 수입 · 신규 화주 · 이탈 화주
- `table`: 화주 × 구분 한 줄씩 `화주코드 · 구분 · 상대 항 · TEU · 전월 대비 · 비고`. 화주는 `H01…`(수출 표 → 수입 표 순으로 처음 나온 순서), 수출 도착지는 `D01…`, 수입 선적지는 `O01…`
- `review`: 감소 → 이탈 순 한 줄씩 + 건너뛴 줄 + 검산 불일치. 화주 이름을 쓰지 않고 코드와 TEU 숫자만 쓴다
