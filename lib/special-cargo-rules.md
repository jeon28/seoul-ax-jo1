# 스페셜화물 판정 규칙 (special-cargo-rules@v1)

스페셜화물(위험물) 신청을 금지 리스트와 대조해 **가능 / 검토 필요 / 불가** 세 가지로 나누는 규칙. 읽는 이: 이병선(내규 판정) · kim jaehyung(승인 보조).
코드는 `dashboard/js/dgdesk/rules.js` 이고, 화면·결과 파일·테스트가 모두 이 코드를 쓴다. 이 문서와 코드가 다르면 코드가 기준이고, 문서를 고친다.
(필수 서류표 읽는 법은 kim jaehyung 이 이 문서에 이어서 쓴다.)

## 자료

| 파일 | 담는 것 |
|---|---|
| `data/in/special-cargo-rules/prohibit-lists.json` | 금지 리스트: VER.10 (FOR PARTNERS) · VER.11 (SKR HAL ONLY). 금지 UN 번호, Class 전체 금지, 조건부 UN·Class(조건 문구 포함) |
| `data/in/special-cargo-rules/requests.json` | 신청 목록(이름은 Q01 · S01 · L01 코드로 가림) |

VER.11 은 `extends: "v10"` 으로 VER.10 의 UN 번호를 이어받고 `extra_un` 을 더한다. 금지 리스트가 개정되면 이 파일만 바꾸고 `RULES_VERSION` 을 올린다.

## 리스트 고르기

| 발신처 | 적용 |
|---|---|
| SKR · 흥아(HAS/HAL) 계열 (`origin: skr_hal`) | VER.11 (SKR HAL ONLY) |
| 그 외 파트너 (`origin: partner`) | VER.10 (FOR PARTNERS) |

## 표기 통일 (lib/compare.md 와 같은 취지)

- UN 번호: `UN1263` · `UN 1263` · ` 1263 ` → `1263`. 4자리 숫자가 아니면 읽지 못한 것.
- Class: `Class 4.1` · `4.1` → `4.1`. `1`~`9` 또는 `1`~`9` 뒤 `.1`~`.6` 이 아니면 읽지 못한 것.

## 화물 1건 판정 순서

| 순서 | 조건 | 판정 |
|---|---|---|
| 0 | UN 또는 Class 를 못 읽음 | **검토 필요** (가능으로 두지 않는다) |
| 1 | Class 전체 **조건부** (VER.11 의 Class 2) | 검토 필요 |
| 2 | Class 전체 **금지** (VER.10: 1·2·5.2·6.2·7 / VER.11: 1·5.2·6.2·7) | 불가 |
| 3 | UN 이 금지 번호이고 **조건 표에 있음** (ISO 탱크만 · Open top/Reefer 만 · SKR/HAL 선박만 …) | 검토 필요, 단 2 로 이미 불가면 불가 유지 |
| 4 | UN 이 금지 번호이고 조건 표에 없음 | 불가 |
| 5 | 어디에도 안 걸림 | 가능 |

세부 Class(`1.4` · `2.1`)는 세부로 먼저 찾고 없으면 대분류(`1` · `2`)로 찾는다. 5.2 · 6.2 는 세부 그대로만 맞는다(`5.1` · `6.1` 은 걸리지 않는다).

## 신청 판정

한 신청에 화물이 여러 개면 **가장 나쁜 것**이 신청의 판정이다: 불가 > 검토 필요 > 가능. 근거 문구는 가능이면 한 줄(「VER.x 에 해당 없음」), 아니면 걸린 화물의 근거만 ` / ` 로 이어 붙인다.

## 3분류 이름

| 내부 | 에이전트 3분류(결과 파일 `table`) | 화면 줄 이름 |
|---|---|---|
| ok | 가능 | 승인 |
| hold | 검토 필요 | 보류 |
| bad | 불가 | 거절 |

결과 파일의 `review` 에는 검토 필요 · 불가 건과 최근 사고 이력이 있는 건이 올라간다. **검토 필요는 자동 승인하지 않는다.** 최종 승인·발송은 사람이 한다.

## 공유본(DG 승인 데스크)과 다른 점

- Class 세부(`1.4` · `2.1`)도 대분류 규칙을 따른다. 공유본은 글자가 정확히 같을 때만 맞춰 Class 1.x · 2.x 를 놓쳤다.
- UN·Class 를 못 읽으면 보류로 넘긴다. 공유본은 UN 이 비면 가능으로 처리했다.
- 승인안의 조건 문장은 화물마다 따로 붙인다(공유본은 첫 화물 기준).

## 사고 이력

같은 UN 번호의 최근 사고 이력은 `agents/special-cargo-rules/skills/accident-history-lookup/SKILL.md` 가 맡는다. 자료는 `data/in/special-cargo-rules/accident-cases.json`(지금은 가상 8건).

| 항목 | 값 |
|---|---|
| 최근 기간 | **12개월** (`ACCIDENT_MONTHS`): 기준일 12개월 전 날짜(그날 포함) ~ 기준일 |
| 기준일 | 신청 처리 시점의 날짜(`snapshot_at`). 오늘 날짜가 아니다 |
| 기준일 뒤 날짜 | 무시(입력 오류) |

- 판정(가능·검토 필요·불가)은 **바꾸지 않는다.** 최근 사고가 있으면 신청에 붙이고 `review`(「같은 UN 번호 최근 사고 이력」)로 올려 사람이 확인한다.
- 사고 사례 표를 못 읽으면 「조회 불가」로 표시하고 이력이 없다고 처리하지 않는다.
- 회신 초안(승인안·거절안)에는 사고 이력을 넣지 않는다(내부 참고용).
