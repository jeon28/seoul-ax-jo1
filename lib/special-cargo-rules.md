# 승인 보조 (special-cargo-approval@v1)

스페셜화물(DG · OOG · Flexibag) 승인 요청의 **첨부 서류**를 점검하는 규칙. 읽는 이: kim jaehyung(승인 보조). 위의 금지 목록 판정(이병선)은 DG 의 STEP 0 으로 그대로 쓴다.
코드는 `dashboard/js/approval/rules.js` 이고, 화면·결과 파일·테스트가 모두 이 코드를 쓴다. 이 문서와 코드가 다르면 코드가 기준이고, 문서를 고친다.
이 장의 판정 순서와 「애매하면 직접 확인」 원칙은 운항팀 Outlook 업무 메일 자동 초안 모음(`ops-mail-automation`)의 스페셜 화물 승인 흐름에서 옮겼다.

## 자료

| 파일(`data/in/special-cargo-approval/`) | 담는 것 |
|---|---|
| `requests.json` | 승인 요청: 유형 · 선박 · 항로(출발·경유·양하) · 발신처 · 서류별로 뽑은 값(가상 11건) |
| `required-docs.json` | **필수 서류표**: 유형별로 있어야 하는 서류(DG 3 · OOG 4 · Flexibag 3) |
| `limits.json` | 숫자표: 상해·닝보 항구 이름 · 상해 MSDS 농도 · OOG 한도(선박별) · Flexibag 조건(화물 종류 · 충전량 · COA 연도별 양식) |
| `cas-lists.json` | 상해·닝보 양하/경유 CAS 금지 목록(가상 샘플) |
| `imdg-sample.json` | IMDG 대조용 UN별 Class·PG 요약(가상 샘플 10개) |

필수 서류표 읽는 법: `types.<유형>.docs[]` 의 `key` 가 요청의 `docs.<key>` 와 짝이다. `docs.<key>` 가 `null`(또는 없음)이면 그 서류가 안 온 것, 칸 값이 빈 글자이면 서류에 있으나 읽지 못한 것이다.

## 확인 사항의 종류와 판정

| 종류 | 뜻 | 요청 판정 | 초안 |
|---|---|---|---|
| 규정 위반 `violation` | 금지 목록 · 상해·닝보 CAS · OOG 한도 · Flexibag 화물 종류/충전량 | 불가(거절) | 거절 |
| 직접 확인 `unsure` | 못 읽음 · IMDG 불일치 · 금지 목록 조건부 · 상해 MSDS 농도 다름 · 자료 없음 | 확인 필요 | 없음 |
| 서류 누락 `missing` | 필수 서류가 안 옴 | 확인 필요 | 보완 요청 |
| 서류 불일치 `conflict` | 서류끼리 값이 다름 · COA 양식이 연도 양식과 다름 | 확인 필요 | 보완 요청 |

가장 심한 종류(위 표의 위쪽)가 요청의 판정이다. 확인 사항이 없으면 가능(승인). **확신이 낮은 값은 가능으로 두지 않는다.**

## 점검 순서

1. **필수 서류**: 필수 서류표와 비교.
2. **서류 간 대조**: 칸마다 두 서류 이상에 값이 있으면 같아야 한다. 대조 칸 = UN · Class · PG · 중량 · 초과 높이/폭/길이 · 컨테이너.
   - 표기 통일(lib/compare.md 와 같은 취지): `UN1307` = `1307` · `Class 3` = `3` · `PG III` = `III` · `18,000 KGS` = `18000 kg` · `1 m` = `100 cm` = `1000 mm`. `PG` 가 `-` · `N/A` 이면 「없음」으로 보고 대조에서 뺀다.
   - 읽지 못한 칸(단위가 이상하거나 글자)은 직접 확인.
3. **DG** (이 순서 그대로):

   | 단계 | 내용 | 걸리면 |
   |---|---|---|
   | STEP 0 | 금지 목록(VER.10 / VER.11, 위 장). UN·Class 는 선언서 → 요청서 → MSDS 순서로 먼저 읽힌 값 | 불가는 규정 위반, 조건부는 직접 확인 |
   | STEP 0.5 | IMDG 표의 Class · PG 와 대조 | 다르면 **직접 확인**(자동 거절 안 함). 표에 UN 이 없거나 표가 없어도 직접 확인 |
   | STEP 1 | 양하·경유 항구(출발항 제외)가 상해·닝보이면 MSDS 의 CAS 가 그 항구 금지 목록에 있는지 | 있으면 규정 위반. MSDS·CAS·목록이 없거나 못 읽으면 직접 확인 |
   | STEP 2 | 양하·경유 항구가 상해이면 MSDS 농도 = 기준(100%) | 다르면 직접 확인(`sha_msds_on_fail`), 못 읽으면 직접 확인 |

   양하·경유가 상해·닝보가 아니면 STEP 1·2 는 「해당 없음」.
4. **OOG**: 초과 높이·폭·길이·중량이 선박 한도 이하인지. 서류에 적힌 값 중 **가장 큰 값**으로 잰다(서류끼리 다르면 불일치도 따로 나온다). 선박별 한도가 있으면 그 값이 기본 한도보다 먼저. 한도 초과는 규정 위반.
5. **Flexibag**: 화물 종류가 허용 목록(NON-DG)인지, 충전량(서류 중 가장 큰 중량)이 한도 이하인지(위반은 규정 위반). COA 는 인증서 연도의 양식과 같은지: 연도 표에 없으면 직접 확인, 양식이 다르면 서류 불일치.

## 바꿀 때

필수 서류 · 숫자 · 목록은 모두 위 표 파일에 있다. 바꾸면 `RULES_VERSION` 을 올리고 `node scripts/build-special-cargo-approval-result.mjs` 로 결과 파일을 다시 만든다. 값이 가상이라 실제 규정집 값으로 채우는 것은 담당자 몫이다.
