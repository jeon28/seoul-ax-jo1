# 구간 정제

> 에이전트: 소모량 분석 에이전트 (다니엘) · 상태: **작성됨** · 코드: `dashboard/js/bunker/noon-synthetic.js`(정규화) · `performance.js`(`detectOutliers`, `analyze` 의 필터)

## 언제 쓰나
속력별 소모량을 계산하기 전, 항상 첫 단계. 원본 행을 그대로 평균 내면 오타 한 줄이 곡선을 망가뜨린다.

## 입력
NOON REPORT 원본 행: `NOON_DATE, NOONTIME, VYG, RH, AVG_SPD, RPM, SLIP, CONS_IFO, CONS_MGO` (문자열이 섞여 옴).

## 하는 일 (순서대로)
1. **중복 제거**: `날짜|NOONTIME|VYG|RH|AVG_SPD|RPM|SLIP|CONS_IFO|CONS_MGO` 전체가 같은 행만 중복으로 본다(일부만 같은 건 서로 다른 측정). 제거 건수를 센다.
2. **숫자로 바꾸기**: 빈 값·숫자 아님 → 0. 단 `AVG_SPD` 가 숫자가 아닌 글자(`N/A`)면 0 이 아니라 **null(속력 값 오류)** — 어느 속도 묶음에도 넣지 않고 건수만 센다.
3. **입력 오류 의심 표시**: 그 선박의 정상 항해 행(RH ≥ 20, 속력 ≥ 5, FO > 0)이 10개 이상이면, 하루 환산 FO(= FO ÷ RH × 24)의 **중앙값 × 5** 를 상한으로 잡고, 하루 환산 FO 또는 MGO 가 넘는 행에 `outlier` 표시. 10개 미만이면 아무것도 표시하지 않는다.
4. **조건으로 거르기**(`analyze` 안): RH 23~25, Slip −10~10, 속력 10~22kn, 기간. 범위는 양 끝 포함. 「입력 오류 의심 행 제외」를 끄면 표시된 행도 평균에 넣는다.

## 출력
쓸 행 목록 + 제외 건수(중복 · 입력 오류 의심 · 속력 값 오류). 화면 문구: "NOON REPORT N건 (기간) 중 조건에 맞는 M건 사용 · 중복 a건 제거 · 입력 오류 의심 b건 제외 · 속력 값 오류 c건 제외".

## 확인 필요로 넘길 때
- 입력 오류 의심이 한 선박에서 5건 이상 → 「입력 오류 의심 행 많음」(원본 확인).
- 제외한 행을 어떻게 판단했는지는 항상 건수로 남긴다(말없이 지우지 않는다).
