# 사고 이력 조회

> 에이전트: 스페셜화물 내규 판정 에이전트 (이병선) · 상태: **작성됨** · 코드: `dashboard/js/dgdesk/rules.js`(`lookupAccidents` · `cleanAccidents` · `accidentText`) · 자료: `data/in/special-cargo-rules/accident-cases.json`(**가상**)

## 언제 쓰나
금지 매트릭스 판정(`prohibit-matrix-judge`) 뒤. 담당자가 같은 UN 번호의 최근 사고를 기억에 의존하지 않고 같은 정보로 보게 하려고. 담당자가 바뀌거나 부재 중이어도, 못 들은 최근 사고도 반영된다(품질 문제).

## 입력
- 판정된 신청의 화물 UN 번호(`prohibit-matrix-judge` 출력).
- 사고 사례 표 `accident-cases.json`: 사고코드(A01…) · UN 번호 · Class · 사고 유형 · 날짜(YYYY-MM-DD) · 출처 코드. 선사·선박 이름은 넣지 않는다. 지금은 **가상 8건**.
- 기준일: 신청 처리 시점의 날짜(`requests.json` 의 `snapshot_at`). 같은 자료면 언제 돌려도 같은 결과가 나오게 오늘 날짜를 쓰지 않는다.

## 숫자표

| 항목 | 값 | 뜻 |
|---|---|---|
| 최근 기간 | **12개월** (`ACCIDENT_MONTHS`) | 기준일 12개월 전 날짜 이후(그날 포함) ~ 기준일 |
| 기준일 뒤 날짜 | 무시 | 미래 날짜는 입력 오류로 본다 |

숫자를 바꾸면 `lib/special-cargo-rules.md` 도 함께 고치고 `RULES_VERSION` 을 올린다.

## 하는 일 (순서대로)
1. 사고 사례 표에서 형식이 안 맞는 행(UN 번호 4자리 아님 · 날짜 형식 아님 · 유형 없음)을 버리고 개수를 센다. UN 표기는 통일한다(`UN1381` → `1381`, `lib/compare.md`).
2. 신청 화물의 UN 번호마다 같은 UN 의 사고를 찾아, 최근 12개월 안(최신순)과 그 이전 건수로 나눈다.
3. 신청에 `{ recent[], older }` 를 붙인다. 문장: 「최근 12개월 사고 N건 (가장 최근 날짜 UN 유형)」 / 「최근 12개월 없음 (그 이전 N건)」 / 「기록 없음」.
4. 최근 사고가 있으면 그 신청을 `review` 로 올린다: 사유 「같은 UN 번호 최근 사고 이력」.

## 출력
- 신청마다 사고 이력 → 화면 카드의 「최근 사고 N건」 배지, 회신 시트의 「사고 이력」 줄과 사고 목록.
- 결과 파일: `table` 의 「사고 이력」 칸, `metrics` 의 `accident`(최근 사고 이력이 붙은 신청 수), `review` 의 「같은 UN 번호 최근 사고 이력」.
- **판정(가능·검토 필요·불가)은 바꾸지 않는다.** 사고 이력은 사람이 볼 참고 정보이고, 최종 판단은 담당자가 한다.
- 사고 이력은 내부 참고용이라 회신 초안(승인안·거절안)에는 넣지 않는다. 넣을지는 담당이 정한다.

## 확인 필요로 넘길 때
- 최근 사고 이력이 있으면 가능으로 나온 건도 확인 필요로 넘긴다(자동 승인하지 않는다).
- 사고 사례 표를 못 읽었으면 「사고 이력 조회 불가」로 표시하고, **이력이 없다고 처리하지 않는다**. 금지 리스트 판정은 계속한다.
- 사고 사례 표에 형식이 안 맞는 행이 있으면 `review` 에 「형식이 맞지 않는 사고 사례 행」으로 올린다.

## 남은 일
- 지금 표는 **가상**이다. 실제 운영은 매주 정해진 시간에 해사 뉴스·사고 공지(예: Splash247, gCaptain, Lloyd's List)에서 위험물 사고만 골라 UN 번호·Class·유형·날짜·출처 링크로 팀 공유 엑셀이나 SharePoint 목록에 쌓고, 이 파일 꼴로 바꿔 읽는 입력부를 붙인다.
- CINS 같은 업계 사고 자료는 회원사 전용일 수 있어 회사의 접근 권한을 먼저 확인한다.
- 실제 사고를 넣을 때도 선사·선박 이름은 `lib/mask.md` 코드로 가리거나 아예 쓰지 않는다.
