# 판정 기록

> 에이전트: 스페셜화물 내규 판정 에이전트 (이병선) · 상태: **작성됨** · 코드: `dashboard/js/dgdesk/drafts.js`(초안 문구) · `scripts/build-special-cargo-rules-result.mjs`(결과 파일) · 화면: `dashboard/js/dgdesk/board.js`

## 언제 쓰나
판정이 끝난 뒤 마지막 단계. 모든 판정을 기록으로 남겨 월간 통계·감사에 쓰고, 담당자가 확인할 회신 초안을 준비한다. 발송은 하지 않는다.

## 입력
판정된 신청 목록(`prohibit-matrix-judge` 출력)과 신청마다 붙은 사고 이력(`accident-history-lookup` 출력).

## 하는 일 (순서대로)
1. **3분류로 나누기**: 승인(가능) · 보류(검토 필요) · 거절(불가). 건수를 센다.
2. **기록**: 신청 한 건을 결과 파일 `table` 한 행으로(요청코드 · 선박 · 구간 · UN·Class · 적용 리스트 · 판정 · 근거), 보류·불가는 `review` 로. `headline` 은 「N건 판정: 가능 a · 불가 b · 검토 필요 c, 최근 사고 이력 d건」. 사고 이력은 `table` 의 「사고 이력」 칸과 `review`(「같은 UN 번호 최근 사고 이력」)에 함께 적는다.
3. **회신 초안 만들기**(글만):
   - 승인 건 → **승인안**(승인 문구 + 슬롯·IMO 규정·추가 비용 단서).
   - 거절 건 → **거절안**(금지 리스트 해당 UN·Class 와 리스트 이름을 건마다 적음).
   - 보류 건 → **승인안 + 거절안 둘 다**. 승인안에는 조건 문장(예: `UN 1381 is accepted only under the condition below: ISO TANK & UNDER WATER …`), 거절안에는 「조건이 신청서에 확인되지 않음 · 조건 충족 시 재신청」 안내. 복사할 때 맨 위에 `// 보류, 사용자 추가 확인 요함//` 표시를 붙인다(보낼 때는 지운다).
4. 선박명·부킹번호·서명은 [대괄호] 자리표시로 두어 사람이 원 메일을 보고 채운다.

## 출력
`data/out/special-cargo-rules.json`(`node scripts/build-special-cargo-rules-result.mjs`)과 화면의 회신 초안 시트. 초안은 화면에서 고칠 수 있고 「초안 복사」로 복사한다.

## 확인 필요로 넘길 때
- 보류 건은 담당자가 조건을 확인한 뒤 승인안·거절안 중 하나를 고른다(자동 승인 금지).
- 불가 건도 거절 회신을 담당자가 확인한다.
- 초안 문구는 선사 표준 문구를 옮긴 것이라, 문구를 바꾸려면 `drafts.js` 를 고친다.

## 하지 않는 것
메일 보내기, Outlook 임시보관함 저장(공유본에는 있었으나 이 대시보드 규칙(보내기 없음)에 따라 뺐다).
