# 월간 거래처 집계

> 에이전트: 영업실적 분석 에이전트 (노현석) · 상태: **작성됨** · 코드: `dashboard/js/sales/rules.js` 의 `readSheet` · `aggregate` · `noteOf` · `topPorts` · `portColumns`

## 언제 쓰나
월별 거래처 실적 엑셀을 받으면 항상 첫 단계. 병목의 ⭐ 최우선 지점(수출은 도착지별, 수입은 선적지별 물동량을 다시 나누는 일)과 그 앞뒤 집계(화주별 → 전월 비교·신규 표시 → 표 2장)를 이 스킬이 맡는다.

## 입력
실적 엑셀 첫 시트(배열의 배열)와 이번 달 · 전월. 머리글 행에 `월 · 화주 · 구분 · POD/POL(또는 POD · POL) · TEU` 가 없으면 "머리글을 찾지 못했습니다 / 머리글에 없는 칸: …" 으로 멈춘다. 전월은 사람이 고르고, 고르지 않으면 비교하지 않는다.

## 하는 일 (순서대로)
1. **읽기·표기 통일** (`lib/aggregate.md`): 구분(`EXP` → 수출) · 화주(`(주)` 제거) · 항구(영문 대문자) · TEU(`1,200` → 1200) · 월(`2026.10.05` → 2026-10). 합계 줄은 건너뛴다.
2. **걸러내기**: 월 · 화주 · 구분 · 항구 · TEU 중 비었거나 읽지 못한 줄은 집계에서 빼고 줄 번호와 이유를 적는다. 값을 짐작해서 채우지 않는다.
3. **화주별 집계**: 구분(수출/수입)마다 화주별 항구별 TEU 를 더한다. 이번 달 · 전월 · 증감 · 비고를 붙이고 이번 달 TEU 큰 순(같으면 이름 순, 이탈은 맨 아래)으로 놓는다.
4. **비고 표시**: 전월 0 → `신규` · 이번 달 0 → `이탈` · 증감 +5 TEU 이상 → `증가` · −5 TEU 이하 → `감소`(구분마다 따로 본다).
5. **항구별 집계**: 건에서 따로 한 번 더 묶는다(수출은 도착지, 수입은 선적지): 이번 달 · 전월 · 증감 · 비중 · 화주 수.
6. **검산 5개**: 원본 합계 = 표 합계 + 뺀 줄 · 화주별 합계 = 항구 칸 합 · 수출 항구 칸 합계 · 수입 항구 칸 합계 · 전월 합계 = 전월 자료 합계.

## 출력
- 구분별 화주 목록(이번 달 · 전월 · 증감 · 비고 · 항구별 TEU)과 항구별 목록, 검산 결과, 읽지 못한 줄 목록. 화면의 「영업 카드」(합계 3장 · 화주 변화 · 항구 상위 3)와 「월간 실적 보고서」(수출표 · 수입표, 항구 8곳 넘으면 위 7곳 + 기타)가 이 값을 그린다.
- `data/out/pyeongtaek-sales.json` 의 `table`(화주 × 구분 한 줄) · `metrics` · `headline`. 화주는 `H01`, 항구는 `D01`(수출) · `O01`(수입) 로 가린다.
- 가상 샘플(`demo-monthly-sales.xlsx`)의 기대 결과: 수출 241 TEU(전월 220, +9.5%) · 수입 158 TEU(전월 162, −2.5%). 신규 2(수출 1 · 수입 1) · 이탈 2 · 증가 3 · 감소 2. 검산 5개 모두 일치.

## 확인 필요로 넘길 때
맞다고 처리하지 않고 `review` 에 넣는다.
- 읽지 못한 줄이 하나라도 있음 → 「건너뛴 줄: 엑셀 N줄을 읽지 못해 집계에서 뺐음(월·화주·구분·항구·TEU 확인 필요)」
- 검산이 맞지 않음 → 「검산 … 이(가) 맞지 않음」
- 전월 대비 큰 폭 감소 · 이탈 화주 → 「H13 수입 TEU 37→22 (−15), 방문 우선 검토」「H09 수출 이번 달 실적 0, 전월 11」
- 전월 자료를 고르지 않음 → 비교 칸을 0 으로 두지 않고 `확인 필요` 로 표시한다.
`review` 의 `detail` 에는 화주·항구 이름을 쓰지 않고 코드와 TEU 숫자만 쓴다.
